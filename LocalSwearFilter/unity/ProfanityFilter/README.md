# ProfanityFilter — фильтр мата для Unity

Локальный фильтр мата для чата: русский и английский подробно (обходы:
пробелы/точки между буквами, цифры и латиница вместо букв, повторы, транслит,
звёздочки-самоцензура), немецкий/испанский/турецкий/японский — базово.
Без сервера, без regex, без зависимостей — работает на WebGL/IL2CPP.
~0.01–0.02 мс на сообщение, словари компилируются один раз при первом вызове.

## Установка

Скопируй папку `ProfanityFilter` целиком куда угодно внутрь `Assets/`. Всё.

- Папку `Tests/` можно удалить — на работу фильтра она не влияет.
- Если в консоли появилась ошибка про Test Framework — просто удали `Tests/`
  (или поставь пакет Test Framework в Package Manager).

## Использование

```csharp
// При ОТПРАВКЕ сообщения:
string safe = ChatProfanityFilter.Censor(inputField.text);   // мат → ***
SendToChat(safe);

// При ПОЛУЧЕНИИ — перед отображением (обязательно!):
chatLine.text = ChatProfanityFilter.Censor(incomingMessage);
```

Фильтровать нужно **в обе стороны**: входящие сообщения тоже, иначе игрок со
старым билдом (или обошедший фильтр ввода) покажет мат остальным.

Дополнительно:

```csharp
bool bad = ChatProfanityFilter.IsProfane(text);  // только проверка, без замены
var r = ChatProfanityFilter.Check(text);          // r.Profane, r.Censored, r.Hits (что и где найдено)
ChatProfanityFilter.Warmup();                     // прогрев на старте (опционально):
                                                  // первый вызов загружает словари (~единицы мс)
```

## Словари

Лежат в `Resources/ProfanityFilter/*.txt` — по файлу на язык. Правятся
блокнотом, перекомпиляция не нужна (но нужен перезапуск игры — словари
читаются один раз при первом вызове).

Самое нужное — две секции в конце файла:

- **`[roots]`** — корни мата. Ищутся как подстроки нормализованного текста:
  корень `пизд` ловит и «пиздец», и «спиздили», и «п и з д а», и «pizdec».
  Добавляй основу слова, а НЕ варианты написания — обходы (пробелы, цифры,
  транслит) снимает нормализация автоматически.
- **`[whitelist]`** — обычные слова, внутри которых корень срабатывает ложно
  («команда» ← манд, «застрахуй» ← хуй). Достаточно основы без окончания:
  «барсук» покрывает «барсука», «барсуки» и т.д.

Остальные секции (таблицы замен, диграфы транслита, native-варианты) лучше
не трогать без понимания — они описаны комментариями в JS-стенде, который
является источником правды для этих файлов.

**Рекомендуемый процесс:** новые слова сначала проверяются на HTML-стенде
(папка `chat-filter` рядом, открыть `index.html`): там видно ложные
срабатывания сразу и есть 500+ автотестов. После правки JS-словарей выполните
`node export-unity-data.js` — он перегенерирует эти .txt и тест-кейсы.
Если стенда под рукой нет — можно править .txt напрямую, формат одинаковый.

## Тесты

Window → General → Test Runner → EditMode → Run All. Прогоняется тот же корпус
из 500+ кейсов, что и на стенде: мат, обходы, транслит и чистые фразы, на
которых фильтр когда-то ложно срабатывал.

## Ограничения (by design)

- Ложные срабатывания возможны на стыках слов («спи здесь» → «пизд») —
  политика «лучше перефильтровать»; частые случаи уже в whitelist.
- Завуалированная похабщина без матерного корня («сядь на бутылку») не
  ловится — это граница корневого подхода.
- `Censor` ставит `*` ровно по найденному диапазону; соседние буквы могут
  попасть под замену при склейке слов — это нормально.
