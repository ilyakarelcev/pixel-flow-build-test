# Game Design Document: Swipe & Merge Puzzle (Working Title)

## 1. Общее описание (Vision)
Игра представляет собой гибрид базовой механики головоломки 2048 и структурной прогрессии Match-3 (Candy Crush, Playrix games).
Игрок перемещает объекты по сетке свайпами, собирает нужные числа для выполнения миссий уровня, а также преодолевает препятствия и решает пространственные задачи. Гравитация в игре полностью отсутствует (как в 2048).

## 2. Управление и Core Loop
* **Ввод:** Свайпы по экрану (Вверх, Вниз, Влево, Вправо), а также стрелки клавиатуры и WASD (для Web/PC).
* **Событие хода (Turn):** При вводе ВСЕ подвижные объекты на карте пытаются одновременно скользить в выбранном направлении по прямой линии до упора в границу поля или другое препятствие.
* **Холостые ходы:** Если ввод игрока в определенную сторону не может сдвинуть ни один объект на поле и не приводит ни к одному слиянию (мёрджу), этот ввод ИГНОРИРУЕТСЯ. Ход не расходуется, счетчик ходов не уменьшается, новый кубик не спавнится.
* **Цель кор-лупа:** Выполнить перечень Миссий за ограниченное количество ходов на уровне.

## 3. Физика перемещения и Слияния
* **Логика слияния (Merge):** Поскольку при свайпе все блоки летят в одном направлении, слияние происходит, когда летящий «Числовой Блок» "догоняет" (врезается в) другой такой же блок, который уже остановился из-за препятствия или края поля. Они сливаются в один блок со значением `X * 2`.
* **Лимит слияний за ход:** Кубик, образованный путем слияния в текущем ходу, **не может** слиться повторно в течение этого же хода (правило 2048: например `2, 2, 4` при свайпе в сторону стене превратятся в `[ ], 4, 4`, а не в `8`).
* **Моментальный сбор (Освобождение места):** Если в ходе уровня игроку поручено выполнить миссию "Собрать блок 16", процесс выглядит так: все блоки сначала совершают свои перемещения и слияния (как в классической 2048). Блок, двигающийся позади летящей «8», врезается в новообразованную «16». **Только после полного завершения всех перемещений** за текущий ход, целевой куб «16» исчезает с игрового поля и зачисляется в UI-счетчик миссии. Никаких "невидимых стен" во время движения нет.

## 4. Сетка и Форма уровней
Поле игры не обязано быть прямоугольным. Оно описывается набором координат доступных ячеек.
* **Ячейка (Cell):** Имеет координаты X, Y. Если координаты нет в списке клеток уровня — это "Дыра". Дыры работают как абсолютно непроходимые стены (граница доски). Кубики доезжают до края доски и упираются в пустоту без риска их "падения".
* Ячейки могут содержать подвижные объекты, статичные препятствия, или быть пустыми проходами.

## 5. Объекты на поле (Бестиарий механик)

Все элементы игры на поле описываются базовыми булевыми свойствами (Movable, Mergeable, Walkable и триггерами уязвимости).

### 5.1. Подвижные объекты (Movable)
* **Числовой Куб:** Обычный элемент механики 2048. Сдвигается, мёрджится. Участвует в миссиях по сбору чисел.
  * *Примечание для разработки:* Для упрощения расчетов в коде, значения кубов следует вычислять в виде "уровней" (степеней двойки). Например: Level 1 = 2, Level 2 = 4, Level 3 = 8, Level 4 = 16 и т.д. В интерфейсах (включая настройки редактора) сдвиг ползунка на 1 шаг будет означать увеличение уровня.
* **Ключ (Подвижный Предмет):** Сдвигается как куб, но не мёрджится ни с чем. Используется для лобового тарана Металлических Дверей.
* **Письмо (Подвижный Предмет):** Сдвигается как куб, но не мёрджится ни с чем. Предназначено для доставки в Почтовые Ящики в рамках миссий уровня.

### 5.2. Статичные Препятствия
* **Простая Стена:** Неподвижна, неразрушима. Физический ограничитель лабиринта поля.
* **Деревянный Ящик (Разрушается мёрджем):** Статичное препятствие, блокирует проезд. Имеет параметр **HP (Жизни, от 1 до 3)**. Ящик теряет 1 HP, если на соседней с ним по кресту (вертикаль/горизонталь) клетке игрок выполнил слияние (мёрдж) любых блоков. Внешний вид ящика меняется в зависимости от оставшегося HP (трещины). **Важно:** урон суммируется. Если за один ход вокруг ящика произошло два мёрджа, он теряет 2 HP. Если мёрдж произошел ровно между двумя ящиками — оба ящика получают по 1 HP урона. При HP=0 исчезает.
* **Замороженный Куб:** Статичное препятствие, внутри которого заперто конкретное число (например, `8` во льду). Блок никуда не сдвигается свайпами. Чтобы растопить его и превратить в обычный числовой блок `8`, игрок должен свайпом ударить об него летящим обычным блоком номиналом `8`. От взрывов соседних мёрджей Замороженный Куб не разрушается! При ударе летящий блок просто останавливается рядом и разрушает лёд. Образовавшиеся два блока `8` (бывший летящий и бывший замороженный) не сливаются в `16` на этом ходу — для слияния потребуется следующий результативный ход.
* **Металлическая Дверь (Разрушается столкновением):** Статичное препятствие. Полный иммунитет к взрывному урону от соседних мёрджей. Разрушается только в том случае, если игрок ударит по ней летящим **Ключом**. При успешном ударе Дверь и Ключ взаимоуничтожаются.
* **Почтовый Ящик (Неразрушимый Приемник):** Статичен, блокирует проезд и никогда не исчезает с поля. Предназначен для сбора **Писем** — особых подвижных объектов. Письма при столкновении с Почтовым Ящиком "поглощаются" им и идут в зачет миссии по сбору Писем. В один Почтовый Ящик можно «вгрузить» неограниченное число писем по ходу уровня.

### 5.3. Активатор Зон (Камень)
* Специфический статичный объект-препятствие.
* Ведет себя как разрушаемый Камень — уничтожается только тогда, когда на соседней с ним клетке происходит слияние (мёрдж) любых блоков.
* При уничтожении этого Камня он мгновенно меняет статус приписанной к нему «Зоны Спавна» с Неактивной на Активную.

## 6. Зоны Спавна (Генерации)
В отличие от 2048, блоки могут спавниться только в заданных зонах на доске. На уровне может быть настроено несколько зон.
* **Параметры Зоны:** Имеет список координат своих клеток; Статус (Активна/Неактивна); и Базовое Число (Base Value, например `N`).
* **Логика случайности номинала:** Если для зоны задано 'Base Value = 8', то новые кубы в ней спавнятся номиналом `8` с шансом **90%**, и номиналом `16` (N*2) с шансом **10%**. Этим правилом управляются все Зоны.
* **Логика мульти-зонности:** После любого результативного хода система ищет все пустые ячейки внутри **всех Активных зон** на поле и кидает **суммарно ровно один кубик за ход** в одну случайную ячейку выбранной зоны. При этом спаунящийся кубик применяет настройки генерации именно той Зоны, в которой он материализовался.

## 7. Прогрессия Уровня (Победа и Поражение)

* **Условия Победы (Миссии) и UI:** Любая миссия концептуально сводится к механике "Собрать X объектов". Все активные миссии жестко закреплены в верхней части экрана (в UI). Каждая отображается как иконка цели (например, сам квадратный блок с цифрой "32" или иконка ящика) и счетчик оставшегося количества рядом с ней. Собирая объекты на доске, мы отправляем их в UI-счетчик. Варианты миссий:
  * **Собрать числа:** Создать N штук целевых числовых кубов (например, собрать три "32").
  * **Собрать разрушаемые объекты:** Разрушить N Деревянных Ящиков. При разрушении ящик как бы "собирается" в миссию.
  * **Собрать ключи/двери:** Открыть N Металлических Дверей. По сути, игрок приносит Ключ в Дверь, и они собираются в интерфейс.
* **Условие Поражения 1 (Лимит ходов):** Счетчик ходов достиг 0, а миссии не выполнены.
* **Условие Поражения 2 (Deadlock / Затор):** Игрок проигрывает досрочно (Game Over), если ВСЕ активные Зоны Спавна полностью забиты объектами (в них нет ни одной пустой клетки) **И** система определяет, что игрок не может сделать ни одного результативного свайпа ни в одном из 4-х направлений (на всем поле ничего не сдвинется и ничего не сольется). Бустеров для спасения не предусмотрено.

## 8. Архитектура JSON Уровней и Интеграция
Уровни хранятся в формате JSON для быстрой загрузки в веб-редакторе. Использование четкого списка координат позволяет создать уровень любой геометрии (крест, кольцо, туннель).

**Важные технологические требования:**
* **Общие стили (Shared CSS):** Визуальное представление (HTML/CSS) всех игровых объектов (блоков, ящиков, стен и т.д.) должно быть общим для самой игры и конструктора уровней. То, как объект выглядит в редакторе, должно на 100% совпадать с тем, как он выглядит в игре.
* **Тестовый загрузчик (Dev Tool):** В интерфейсе самой игры, под игровым полем, должно располагаться текстовое поле для ручной вставки JSON-кода и кнопка `OK`. При нажатии на кнопку игра должна немедленно перезагрузить сцену и загрузить уровень из предоставленного JSON.

### Пример схемы Level-датасета
```json
{
  "level_id": 1,
  "moves_limit": 25,
  "missions": [
    { "type": "collect_block", "target_value": 32, "amount": 2 },
    { "type": "destroy_box", "amount": 5 },
    { "type": "open_door", "amount": 1 }
  ],
  "board_cells": [
    {"x": 0, "y": 0}, {"x": 1, "y": 0}, {"x": 2, "y": 0},
    {"x": 0, "y": 1}, {"x": 1, "y": 1}, {"x": 2, "y": 1}
  ],
  "items": [
    { "type": "block", "x": 0, "y": 0, "value": 2 },
    { "type": "box", "x": 1, "y": 0, "hp": 2 },
    { "type": "frozen_block", "x": 2, "y": 1, "value": 8 },
    { "type": "stone", "x": 1, "y": 1, "activates_zone": "zone_2" },
    { "type": "key", "x": 0, "y": 1 },
    { "type": "door", "x": 2, "y": 0 }
  ],
  "spawn_zones": [
    {
      "id": "zone_1",
      "active": true,
      "base_value": 2,
      "cells": [{"x": 0, "y": 0}, {"x": 0, "y": 1}]
    },
    {
      "id": "zone_2",
      "active": false,
      "base_value": 8,
      "cells": [{"x": 2, "y": 0}, {"x": 2, "y": 1}]
    }
  ]
}
```
* `board_cells` — доступный массив пола (клетки, по которым можно проехать).
* `items` — начальные позиции всех объектов на уровне, включая стены (которые не являются дырами, но проехать через них нельзя).
* `spawn_zones` — разметка генераторов; обратите внимание, что Камень-Активатор (stone) ссылается на ID зоны, которую он включает при своем разрушении.
